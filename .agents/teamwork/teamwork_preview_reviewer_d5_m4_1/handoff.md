## 3. Caveats

- **Message Limit Bounding**: The current implementation of `Summary.tsx` queries up to 100 custom messages (`.setLimit(100)`). In workouts with exceeding volume (>100 custom messages), earlier reps or markers would require pagination (`fetchPrevious()` loop) to aggregate the complete session history. This is acceptable for MVP and matches the exact spec in `ORIGINAL_REQUEST.md` line 477.
- **Offline / Fetch Failure Resilience**: If CometChat message fetching encounters a network error, the component catches the exception, logs a notice, displays a "Retry Fetch" button, and gracefully renders an empty summary baseline without throwing unhandled exceptions or rendering `NaN`.

## 6. Adversarial Challenge Report

### 6.1 Challenge Summary
- **Overall Risk Assessment**: **LOW**

### 6.2 Challenges & Stress Scenarios

#### Challenge 1: Division-by-Zero on Empty or Incomplete Sessions
- **Assumption**: A user might end a workout session without performing any valid repetitions or before the pose detector registers reps.
- **Attack Scenario**: Mount `<Summary>` with `messages = []` or an active session with only `kine.session` start marker.
- **Predicted / Actual Behavior**: `validPct = summary.totalReps > 0 ? Math.round(...) : 0`; `peakDepthDeg` displays `0°`; depth distribution percentage guards against division by zero.
- **Result**: **PASS**. Zero `NaN%` or runtime crashes.

#### Challenge 2: CometChat API Network Failure / Timeout
- **Assumption**: Session history fetch fails due to connectivity drop or token expiration.
- **Attack Scenario**: `fetchPrevious()` rejects with network error.
- **Predicted / Actual Behavior**: Caught in `catch (err)`, error state rendered with a "Retry Fetch" button, and the fallback empty summary avoids cascading UI crashes.
- **Result**: **PASS**. Graceful degradation.

#### Challenge 3: Extreme Valgus Threshold Exceedance
- **Assumption**: Severe knee collapse produces valgus deviations far beyond standard ranges (e.g. +35%).
- **Attack Scenario**: Inject high valgus alert.
- **Predicted / Actual Behavior**: Dark card dynamically highlights max valgus deviation in `var(--status-critical)` if `> VALGUS_THRESHOLD_PCT` (12%), and increments the corresponding bilateral knee luminous pill counter (`summary.alertBreakdown.L` / `R`).
- **Result**: **PASS**.
